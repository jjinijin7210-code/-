# 애니원(AnyOne) 대시보드

AI 직원팀 기반 콘텐츠 운영 대시보드. Vite + React + Tailwind로 만들었고,
Supabase(진짜 DB)를 연결하거나, 연결하지 않아도 브라우저 localStorage로 바로 실행됩니다.

## 🖱️ 바탕화면 아이콘 하나로 실행하기 (컴퓨터 잘 몰라도 OK)

터미널에 명령어 치는 게 번거로우시면, **더블클릭 한 번으로 실행되는 아이콘**을 바탕화면에 만들 수 있어요.
프로젝트 폴더 안에 이미 그 역할을 하는 파일을 만들어뒀습니다.

### Windows

1. 압축을 푼 `anyone-dashboard` 폴더를 엽니다.
2. 그 안에 있는 **`start-anyone.bat`** 파일을 찾습니다.
3. 그 파일 위에서 마우스 오른쪽 버튼 클릭 → **"보내기" → "바탕 화면에 바로 가기 만들기"** 선택.
4. 바탕화면에 아이콘이 생깁니다. (원하면 이름을 "애니원 대시보드"로 바꿔도 돼요 - 오른쪽 클릭 → 이름 바꾸기)
5. **이 아이콘을 더블클릭**하면:
   - 처음 한 번은 필요한 프로그램을 자동으로 설치해요 (몇 분 걸릴 수 있어요, 창에 안내 문구가 나와요)
   - 서버가 켜지는 검은 창이 하나 뜨고, 몇 초 뒤 브라우저가 자동으로 열려요
6. **끄고 싶을 땐** "애니원 대시보드 서버" 라고 써있는 검은 창을 닫으면 돼요.
7. 만약 실행 시 파란 보안 경고("Windows의 PC 보호")가 뜨면 "추가 정보" → "실행" 을 눌러주세요
   (직접 만든 파일이라 안전합니다).

### Mac

1. 압축을 푼 `anyone-dashboard` 폴더를 엽니다.
2. 그 안에 있는 **`start-anyone.command`** 파일을 찾습니다.
3. **처음 한 번만**: 그 파일을 Control 키를 누른 채 클릭(또는 마우스 오른쪽 클릭) → "열기" 선택
   → 경고창이 뜨면 다시 한번 "열기" 눌러서 허용해줍니다. (macOS 보안 정책 때문에 첫 실행만 이렇게 해요)
4. 바탕화면에 두고 싶다면, 그 파일을 마우스 오른쪽 클릭 → "다른 폴더에 앨리어스 만들기" →
   만들어진 앨리어스 파일을 바탕화면(Desktop)으로 옮깁니다.
5. 이후로는 그 아이콘을 그냥 더블클릭하면 서버가 켜지고 브라우저가 자동으로 열립니다.
6. **끄고 싶을 땐** 열려있는 터미널 창을 닫거나 `Ctrl + C`를 누르세요.

### 참고
- 이 아이콘들은 결국 이전에 안내드린 `npm run dev:all` 명령을 대신 눌러주는 것뿐이라,
  터미널로 직접 실행하시던 것과 완전히 동일하게 동작해요.
- 이 방법도 **로컬 개발 서버를 실행하는 것**이라, 컴퓨터를 끄면 당연히 다시 켜야 하고
  (아이콘 더블클릭 한 번이면 돼요), 인터넷의 다른 사람이 접속할 수 있는 건 아니에요
  (오직 내 컴퓨터에서만 열려요). 정말 어디서든 접속되는 "배포"가 필요하시면 이후에 별도로
  안내해드릴게요.
- ⚠️ 이 스크립트들은 실제 Windows/Mac 컴퓨터가 없는 환경에서 만들어서, 문법은 표준적인
  방식대로 작성했지만 **실제로 더블클릭해서 작동하는지는 직접 확인하지 못했습니다.**
  안 되면 어떤 메시지가 뜨는지 알려주시면 바로 고칠게요.

## ⭐ 신규: AI 초안 생성 · 자동 검수 · 구글 블로그 연동 (여기부터 꼭 읽어주세요)

이번에 추가된 기능이라 실행 방법이 살짝 달라졌어요. **아래 순서 그대로 따라 하시면 돼요.**

### 무엇이 추가됐나요
1. **콘텐츠 관리 탭의 채널이 5개로 늘었어요**: 블로그(네이버)-인테리어/생활, 블로그(네이버)-푸드,
   블로그(구글 Blogger), 스레드, 인스타/틱톡
2. **스레드·인스타/틱톡 채널**에는 "🤖 AI로 초안 생성" 버튼이 생겨요. 주제만 적으면 Claude가
   계획서의 톤 원칙(20대 초반 타겟, 자연스러운 문체)에 맞춰 초안을 써줘요. 인스타/틱톡은 해외
   트렌드를 참고하되 원문을 그대로 번역하지 않고 새로 재구성하도록 만들었어요.
3. 초안이 생성되면 **자동으로 AI 검수(팩트체크·과장표현·AI스러운 문체)**를 거쳐 통과/반려가
   표시돼요.
4. **구글 블로그(Blogger) 연동 준비**: 계정 연결 버튼과 발행 버튼을 만들어뒀어요. 이미지는
   자동으로 넣지 않고, 직접 본문에 붙여넣으실 수 있게 첨부 영역만 마련했어요.

### 왜 서버가 하나 더 필요해요?
Claude API 키나 구글 로그인 비밀정보는 브라우저(화면)에 그대로 두면 다른 사람이 볼 수 있어서
위험해요. 그래서 이 값들만 따로 다루는 **작은 서버 하나(`server` 폴더)**를 추가했어요. 어렵게
느껴지실 수 있는데, 아래 명령어 한 줄이면 프론트엔드·백엔드가 같이 켜지게 만들어뒀어요.

### 실행 방법 (컴퓨터 켤 때마다 이 순서로)

1. **`.env` 파일에 Claude API 키가 들어있는지 확인** (이미 넣으셨다고 하셨으니 이 단계는 넘어가도 됩니다)
   - 파일 위치: 프로젝트 폴더 바로 안(제일 바깥) `.env`
   - 안에 이렇게 한 줄이 있어야 해요: `ANTHROPIC_API_KEY=sk-ant-...`

2. **터미널(명령 프롬프트) 창을 하나만 여시고, 프로젝트 폴더에서 아래 두 줄을 순서대로 입력**
   ```bash
   npm install
   npm run dev:all
   ```
   (맨 처음 한 번만 `npm install`이 필요해요. 다음부터는 `npm run dev:all` 한 줄이면 돼요.)

   화면에 파란 글씨(FRONT)와 초록 글씨(BACK)가 같이 보이면서, 아래 두 문구가 뜨면 성공이에요.
   - `Local: http://localhost:5173/` (프론트엔드)
   - `[애니원 백엔드] http://localhost:3001 에서 실행 중` (백엔드)

   평소처럼 `http://localhost:5173` 로 접속하시면 됩니다. **이 터미널 창은 계속 켜두세요** —
   닫으면 화면도, "AI로 초안 생성" 기능도 같이 꺼져요.

3. 종료할 땐 터미널 창에서 `Ctrl + C` 한 번이면 프론트·백엔드 둘 다 같이 꺼져요.

> 참고: 예전에 쓰던 `npm run dev` (프론트엔드만 켜기)도 그대로 쓸 수 있어요. 그럴 땐 "AI로
> 초안 생성"·"구글 블로그 발행" 버튼만 동작 안 하고, 나머지 화면은 평소처럼 잘 됩니다.

### 구글 블로그 연동은 아직 "준비" 단계예요
구글 연동은 Google Cloud Console이라는 곳에서 키를 직접 발급받아야 해서, 그 과정까지는 제가
대신해드릴 수 없어요. `.env.example` 파일 아래쪽에 순서대로 적어뒀으니, 여유 있으실 때 하나씩
따라 해보시고, 막히는 부분 있으면 그대로 캡처해서 물어봐 주세요. 안 하셔도 나머지 기능(AI 초안
생성, 콘텐츠 관리 등)은 전부 정상적으로 쓰실 수 있어요.

### 이번 작업에서 실제로 검증한 것 / 못한 것
- ✅ 프롬프트 조립(톤 원칙이 실제로 문구에 들어가는지), AI 응답 파싱(정상/이상한 응답 둘 다),
  구글 인증 URL 생성, 토큰 저장 로직은 전부 **Node.js로 직접 실행해서 검증**했어요
  (아래 "테스트" 섹션 참고).
- ❌ **실제로 Claude API에 진짜 요청을 보내서 글이 잘 써지는지, 구글 로그인이 실제로 되는지는
  이 환경에 네트워크가 없어서 확인하지 못했어요.** 위 실행 방법대로 켜신 뒤 "AI로 초안 생성"
  버튼을 직접 눌러보시고, 이상하면 알려주세요.

- 완료: **URL 검증** - 8단계에서 콘텐츠 관리(링크/발행 URL)에 넣었던 검증을 CS 링크 관리
  (연결 링크)에도 추가했습니다. http(s)://로 시작하지 않으면 저장을 막고 안내 문구를 보여줍니다.
- 완료: **중복 요청 경고** - CS 링크의 트리거 키워드, 루나 요청의 요청 제목이 이미 존재하면
  저장 전에 "그래도 저장할까요?" 확인창이 뜹니다(강제 차단은 아니고, 실수 방지용 경고).
- 완료(이미 3단계 때 구현): **삭제 확인** - 모든 삭제 버튼에 확인창 + 로컬 모드에서는 휴지통
  복구까지 있음.
- 완료(이미 1단계 때 구현): **저장 상태 표시** - 저장중/저장됨/실패가 모든 폼에 표시됨.
- 완료: **오류 메시지** - 필수 항목 누락, URL 형식 오류, 완료 처리 조건 미충족, 자기 승인 시도
  등 각 상황마다 사람이 읽을 수 있는 빨간 안내 문구가 폼 안에 그대로 나옵니다.
- 완료: **Error Boundary** - 앱 어딘가에서 예상 못 한 오류가 나도 화면 전체가 하얗게 꺼지는 대신
  "예상하지 못한 오류가 발생했어요" 안내 화면과 "다시 시도" 버튼이 나오도록 앱 최상단을
  감쌌습니다 (`src/components/ErrorBoundary.jsx`).
- 완료(설계로 이미 만족): **모바일 대응 / 긴 표 가로 스크롤** - 처음부터 실제 HTML `<table>`
  대신 카드형 레이아웃으로 만들어서, 좁은 화면에서 표가 잘리거나 가로 스크롤이 필요한 상황
  자체가 거의 없습니다. 필터·태그처럼 한 줄에 안 들어갈 수 있는 요소들은 전부 `flex-wrap`으로
  줄바꿈되게 해뒀습니다.
- 완료: 필수 항목 검증/중복 감지 순수 로직을 `scripts/test-validation.mjs`로(9/9 통과),
  Error Boundary의 상태 계산 로직을 `scripts/test-error-boundary.mjs`로(4/4 통과) Node.js에서
  실제 실행 검증했습니다. 특히 FormField의 `required` 속성이 **정말로 실제 HTML에 반영되는지는
  추측하지 않고**, `react-dom/server`로 컴포넌트를 진짜 렌더링해서 `<input required>` /
  `<textarea required>`가 실제로 만들어지는지 `scripts/test-formfield-render.mjs`로 확인했습니다
  (5/5 통과 - `npm install` 후 실행 가능, 그 전엔 esbuild가 없어서 안내 후 종료됩니다).
- **중요한 발견 (정직하게 보고드립니다)**: 처음에는 Error Boundary가 실제로 하위 컴포넌트의
  에러를 잡는 것까지 `react-dom/server`로 렌더링해서 확인하려 했는데, 실행해보니 **React의
  구버전 서버 렌더러(renderToStaticMarkup)는 클래스형 Error Boundary의 에러 캐치를 지원하지
  않는다**는 걸 실제 실행 중 에러로 확인했습니다. 이건 브라우저(클라이언트) 렌더링에서만
  동작하는 React의 표준 동작이라 코드 자체는 정상이라고 판단하지만, "정말로 화면이 하얗게
  꺼지지 않는지"는 브라우저에서 직접 확인해야 하는 부분이라 **미확인으로 남겨둡니다.**
  (해당 시도는 테스트에 포함하지 않고 제거했습니다 - 검증되지 않은 걸 검증됐다고 남기지 않기 위해)
- 미확인: 모바일 실제 화면, 필수/URL/중복 검증 메시지가 브라우저에서 기대대로 뜨는지.

## 1. 로컬 실행 방법 (macOS/Linux)

이 코드는 여기(claude.ai 컨테이너)에서는 네트워크가 막혀 있어 npm install을 실제로
돌려보지 못했습니다. 본인 컴퓨터에서 아래 순서대로 진행해주세요.

```bash
# 1) 압축 풀고 폴더로 이동
cd anyone-dashboard

# 2) 패키지 설치
npm install

# 3) (선택) Supabase를 쓰려면 환경변수 파일 만들기 - 안 하면 자동으로 localStorage 모드로 실행됩니다
cp .env.example .env
# .env 파일을 열어서 VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY 값을 채워넣기

# 4) 개발 서버 실행
npm run dev
# http://localhost:5173 에서 확인
```

## 1-1. Windows에서 실행하는 방법

1. Node.js 설치: https://nodejs.org 접속 -> "LTS" 버전 다운로드 후 설치 (설치 마법사 그대로 "다음"만 누르면 됩니다)
2. 설치가 끝나면 시작 메뉴에서 "PowerShell" 또는 "명령 프롬프트(cmd)" 검색해서 실행
3. 압축 푼 폴더로 이동 (예: 바탕화면에 풀었다면)
   ```powershell
   cd Desktop\anyone-dashboard
   ```
4. 아래 명령을 순서대로 입력 (각 줄 입력 후 Enter)
   ```powershell
   npm install
   npm run dev:all
   ```
   (AI 초안 생성 기능 없이 화면만 켜고 싶다면 `npm run dev`만 입력해도 돼요.)
5. 화면에 "Local: http://localhost:5173/" 같은 문구가 뜨면, 그 주소를 크롬/엣지 주소창에 붙여넣기

   - "npm은 내부 또는 외부 명령... 인식되지 않습니다" -> Node.js 설치가 안 됐거나, 설치 후
     PowerShell을 새로 열지 않은 경우입니다. PowerShell을 완전히 껐다가 다시 열어보세요.
   - 방화벽/백신이 팝업을 띄우면 "허용"을 눌러주세요.
   - 종료하려면 실행 중인 창에서 Ctrl + C

## 3. Supabase 설정 (선택 사항 - 실제 DB로 여러 기기에서 공유하고 싶을 때)

1. https://supabase.com 에서 무료 프로젝트 생성
2. Project Settings > API 에서 Project URL과 anon public key 복사 -> .env에 붙여넣기
3. SQL Editor로 이동 -> supabase/schema.sql 파일 내용 전체를 복사해서 붙여넣고 실행
4. Authentication > Users 에서 본인이 로그인할 이메일/비밀번호로 사용자 1명 직접 추가
   - .env를 채우는 순간부터 로그인 화면이 나타납니다. 채우지 않으면 로그인 없이 바로 사용됩니다.
